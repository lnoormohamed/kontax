### Ticket Details

#### P34-01 — Contact avatar fallback for company-only contacts

**Problem:** Contacts with no first or last name (company-only contacts like "Barclays") show an empty avatar circle with no text in the contact detail header and elsewhere.

**Fix:**
- When `fullName` is blank/empty but `company` is set, derive initials from the company name using the same initials logic (first letter of each word, capped at 2). E.g. "Barclays" → "BA", "General Electric" → "GE".
- When there is truly nothing (no name, no company), show a generic person silhouette icon instead of an empty coloured circle — an empty circle with a colour tint looks broken.
- Affects all avatar surfaces:
  - Contact detail page hero avatar (`/contacts/[id]`)
  - `ContactAvatar` in `contacts-workspace-table.tsx` (list rows)
  - `ContactAvatar` in `search-results.tsx` (search dropdown and overlay)
  - Mobile contact detail hero
- The tint colour should still be derived from `fullName ?? company ?? "?"` so it's stable.

**Acceptance:** A contact with only a company name shows company initials in the avatar. A contact with nothing shows a person icon.

#### P34-04 — Tablet responsive layout audit & fixes

**Problem:** Several settings and sync pages have layout issues in the 768px–1024px tablet range.

**Scope of audit:**
- `/sync` — the two-column layout (account list + detail panel) collapses badly at ~768px. The account list becomes too narrow, the detail panel overflows. Fix: at tablet width, stack the panels or use a responsive split that matches the contacts list pattern.
- `/settings/sync` — same issue as `/sync` (if they share the layout).
- Settings subpages generally: the sidebar + main content pattern doesn't adapt gracefully to 768px. At tablet widths the sidebar is too narrow to read and the content area is too compressed.
- Contact detail page: the two-panel split (left: hero, right: tabs+fields) at ~768px sometimes renders the right panel too narrow.

**Fix approach:**
- Define a breakpoint at 900px where two-column settings layouts collapse to a single column with the sidebar becoming a top tab strip or a "back" navigation pattern.
- The sync account list and detail panel should stack at <900px, with the detail panel shown after selection (slide in or replace).
- Document all affected pages and fix the worst-offending ones. Log the rest as follow-up.

#### P34-06 — Expand preferences section

**Problem:** The current preferences panel in settings has few options, making it feel thin compared to the account and security sections.

**New preferences to add:**

| Preference | Options | Default |
|---|---|---|
| Default contact sort | Name A–Z / Last modified | Name A–Z |
| Default view mode | Compact / Cozy | Compact |
| Date display format | DD MMM YYYY / MM/DD/YYYY / YYYY-MM-DD | DD MMM YYYY |
| Week starts on | Monday / Sunday | Monday |
| Contact name display | First Last / Last, First | First Last |
| Show contact count in sidebar | On / Off | On |

Store in a `UserPreferences` JSON column on `User` (or a separate `UserPreference` table if you want per-key querying). Preferences are applied at render time in server components — read the preference from the session/DB and pass down as props.

**Implementation notes:**
- `name display` preference affects how contacts are rendered in list rows and the contact detail header. Requires threading through `ContactsWorkspaceTable` and the detail page.
- `default sort` and `view mode` replace the URL-param defaults — if the URL doesn't specify, fall back to the user's preference rather than a hardcoded default.
- Date format applies to all date fields in the contact detail (Added, Modified, Birthday, significant dates).

#### P34-07 — Smarter duplicate detection & merge review

**Problem:** The current merge suggestion system flags duplicates but doesn't tell the user *why* they're flagged, and re-surfaces dismissed pairs. The merge UI is a flat list with no field-level comparison.

**Improvements:**

1. **Match reason display** — each duplicate pair card shows which fields matched and the confidence: e.g. "Same phone number", "Very similar name (John Smith / John D. Smith)", "Same email".
2. **Persistent "not a duplicate" dismiss** — store dismissed pairs in a `MergeDismissal` table (`userId, contactAId, contactBId, dismissedAt`). Never re-surface a dismissed pair unless the user explicitly clears dismissals.
3. **Improved scoring weights:**
   - Exact phone match → high confidence (0.95)
   - Exact email match → high confidence (0.95)
   - Exact full name → medium-high (0.8)
   - Fuzzy name (Levenshtein ≤ 2) + same company → medium (0.65)
   - Fuzzy name alone → low (0.4) — only surface if confidence ≥ 0.5
4. **Side-by-side field preview** — the merge card expands to show both contacts' fields side by side so the user can see what's different before merging.
5. **Merge conflict resolution** — when merging, let the user choose which value wins for each conflicting field (rather than always taking the "winner" contact's value).

**Schema additions:**
```prisma
model MergeDismissal {
  id          String   @id @default(cuid())
  userId      String
  contactAId  String
  contactBId  String
  dismissedAt DateTime @default(now())
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@unique([userId, contactAId, contactBId])
}
```

#### P34A-09 — Pre-prod checklist run-through
